# Task-flow

## Overview

Работа над задачей идёт по фиксированным стадиям, а порядок и проверки держит CLI `flow`, а не память агента. Агент делает творческую часть стадии (текст документа, код, правки), всё остальное — пути, правила, показ в Plannotator, проверка доказательств, статус Jira — делает код.

CLI: `node <base>/../../tools/flow/cli/main.mts <команда>`, где `<base>` — «Base directory for this skill». Ответ — JSON с полем `result`; `--text` печатает его для человека.

## Цикл

1. `flow status` — где задача и какая стадия текущая. Задачи нет — `flow start <ключ или ссылка Jira>` (`--no-tracker` для задачи без Jira, `--step-dir <папка шага>` для шага роадмапа).
2. `flow next --agent <ваше имя: claude, codex, opencode…>` — рабочий пакет текущей стадии (имя агента нужно, чтобы стадия `simplify` выдала доступный вам вариант): куда писать, какие правила прочитать, каким должен быть результат. Правила кита лежат в пакете текстом.
3. Выполните работу стадии по пакету.
4. Закройте стадию:
   - документы (`spec`, `test-plan`, `plan`): `flow validate`, затем `flow submit` и `flow wait`;
   - `implement`, `simplify`, `check`, `local-test`: запишите итог в файл из пакета и выполните `flow done <стадия> --evidence <файл>`;
   - `review`: `flow submit`, затем `flow wait`;
   - `pr`: `flow done pr --evidence <URL PR>`.
5. Повторяйте с шага 1, пока `status` не покажет, что задача завершена.

## Как действовать по ответу

- `ok` — продолжайте.
- `blocked` — предусловие не выполнено; прочитайте `reason` и устраните причину. Не обходите отказ.
- `needs-input` — задайте пользователю вопрос из ответа дословно с вариантами и продолжайте по его ответу (на `implement` — `flow next --method <метод>`).
- `pending` — показ идёт в Plannotator: выполните `flow wait` (повторяйте при таймауте).
- `annotated` — исправьте замечания в том же файле и снова `flow submit`.
- `review-feedback` — внешнее ревью документа нашло замечания: прочитайте отчёт по `reportPath`, исправьте документ и выполните то, что сказано в поле `instruction`.
- `dismissed` — согласование отклонено: стадия остаётся открытой; сообщите пользователю, что согласования нет, и не продолжайте дальше.
- `approved` — стадия закрыта; переходите к следующей без вопроса.

## Жёсткие правила

- Не правьте `tmp/flow/*.json` вручную и не пропускайте стадии молча: `flow skip <стадия> --reason "<причина>"` — единственный способ, причина записывается.
- Переход от плана к реализации требует согласия пользователя: его оформляет `flow next` как `needs-input` с выбором метода. Переходы между документами идут без вопросов.
- Изменили согласованный документ — его стадия и все следующие вернутся в ожидание; это ожидаемо.
- Ревью кода делает только стадия `check`; методы реализации ревью не проводят.
- На стадии `simplify` в Claude Code используйте нативный `/simplify`, в других агентах — `flow next --agent <имя>` подставит skill `kit:simplify`.
- Не коммитьте и не пушьте без явной просьбы пользователя.
- Задача вне флоу (идея без тикета, роадмап, черновик Jira) идёт по прежним правилам кита.

## Границы гарантии

Защита локальная: `flow` ловит забывчивость и сходы с рельсов, но не агента, который сознательно его обходит. Содержимое файлов-доказательств код не проверяет: последний барьер — ревью пользователя.

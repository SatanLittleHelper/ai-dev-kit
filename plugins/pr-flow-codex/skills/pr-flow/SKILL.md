---
name: pr-flow
description: Используй по запросу создать PR, например «сделай ПР», «открой pull request» или «create a PR».
---

1. Определи ветку через `git branch --show-current`. При detached HEAD остановись. Для main, master и default-ветки согласуй имя рабочей ветки по правилам проекта и перейди на неё. Запусти `git status --porcelain`. При наличии относящихся к задаче изменений подготовь один коммит по правилам проекта. Соблюдай действующие требования проекта и среды к разрешениям.
2. По `git remote get-url origin` определи хост и репозиторий. github.com означает GitHub, иной поддерживаемый хост означает Forgejo. Base возьми из `git symbolic-ref --short refs/remotes/origin/HEAD` и удали начальный префикс `origin/` перед передачей имени ветки в gh, Forgejo и CLI. Если ссылки нет, уточни base. При отсутствии коммитов впереди base остановись.
3. Ищи открытый PR для этой ветки в целевом репозитории. GitHub: `gh pr list --state open --head <ветка> --json url,headRefName`. Forgejo: из корня проекта запусти `node "<каталог-навыка>/../../forgejo.mts" pr find --head "<ветка>"`. Абсолютный каталог навыка возьми из пути SKILL.md. Команда возвращает JSON с полем `url` или `null`, если PR нет. Если PR уже есть, запушь текущую ветку и покажи его ссылку. При неожиданной ошибке поиска остановись, чтобы не создать дубль. Если GitHub CLI недоступен или для Forgejo не задан ни `FORGEJO_TOKEN`, ни `GITEA_TOKEN`, можно запушить ветку и указать, как открыть PR вручную.
4. Для нового PR запиши описание во временный файл. Первая строка — `<эмодзи> **Серьёзность: <уровень>** — <причина>`. Дальше разделы `## Зачем` и `## Что сделано`. 🟢 Лёгкие — документация, тесты, стили, рефакторинг без смены поведения. 🟡 Средние — багфиксы и смена поведения в одном модуле. 🟠 Серьёзные — обратимые миграции, auth, роли, права, инфраструктура, CI, конфиги, env, breaking API, удаление функциональности, сквозные изменения и major-зависимости. 🔴 Критичные — необратимые миграции, платежи, безопасность. Выбери наивысший применимый уровень.
5. До push и создания нового PR найди абсолютный каталог SKILL.md из подключённого навыка или контекста хука. Выполни `sh "<каталог-навыка>/../../hooks/validate.sh" "<base>" "<файл-описания>"` из корня целевого проекта. При ненулевом статусе покажи диагностику и остановись. Если путь к навыку определить не удалось, остановись и предложи восстановить плагин. Этот шаг нужен и при включённых хуках.
6. Выполни `git push -u origin <ветка>`. При отказе остановись и покажи причину. Заголовок — сообщение единственного коммита или краткое название задачи. GitHub: `gh pr create --base <base> --head <ветка> --title <заголовок> --body-file <файл-описания>`. Forgejo: запиши JSON с полями `base`, `head`, `title`, `body`. Возьми `body` целиком из проверенного файла. Запусти `node "<каталог-навыка>/../../forgejo.mts" pr create --file "<черновик.json>" --confirm`. CLI проверит черновик перед отправкой и вернёт `url` и `number`. При ошибке остановись. Если CLI вернул код 3, повтори поиск через `pr find` и проверь результат перед новой попыткой. Токены передавай только через окружение. Покажи ссылку из gh или поле `url` из CLI.

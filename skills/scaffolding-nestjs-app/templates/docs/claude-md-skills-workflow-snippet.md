## Работа со скиллами и субагентами

**Plan Mode перед brainstorming/writing-plans:** при вызове `superpowers:brainstorming` или
`superpowers:writing-plans` — всегда входить в план мод (EnterPlanMode) перед вызовом скилла.

**Правила проекта передавать субагентам явно.** Субагенты (`subagent-driven-development`, `executing-plans` и др.)
не видят контекст текущей сессии и не читают CLAUDE.md/AGENTS.md самостоятельно. Все релевантные конвенции проекта
(структура файлов, запреты, паттерны обработки ошибок, правила логирования) нужно явно копировать в промпт
каждого субагента-имплементера.

**Агент под задачу.** Для каждой задачи плана выбирать агента по специализации: реализация кода —
general-purpose/code-agent, исследование кодовой базы — Explore, планирование архитектуры — Plan. Не назначать
одного агента на всё подряд.

**Коммиты — только по явной просьбе пользователя, во всех скиллах.** `git commit` не выполняется автоматически ни
по завершении отдельной задачи, ни по завершении всего плана — ни в `writing-plans`, ни в
`subagent-driven-development`, ни в `executing-plans`. Планы не должны содержать шаги/упоминания создания коммита.
Промпты имплементер-субагентов явно запрещают `git commit`. Коммит делает пользователь сам или явно просит об этом
отдельной командой.

**Служебные файлы workflow-скиллов — только в `tmp/`, не в git.** Планы, спеки, брифы/репорты, review-пакеты,
build/debug логи раскладывать по подпапкам `tmp/plans/`, `tmp/specs/`, `tmp/reports/`, `tmp/reviews/`, `tmp/logs/` —
не в корень репозитория и не во внешние временные каталоги. Не коммитить спек- и план-файлы в git. Удалять
план-файл после `finishing-a-development-branch` (не сразу после выполнения задач), если пользователь явно не
попросил его сохранить.

**Запрос «запомни» — фиксировать во всех релевантных местах.** Когда пользователь просит что-то запомнить: 1)
зафиксировать в `CLAUDE.md`, если это устойчивое правило проекта; 2) передать явно в промпт субагентам, которые
пишут код — они не читают сессионный контекст; 3) сохранить в auto-memory, если факт переживает текущую сессию и
полезен в будущих разговорах. Применять все пункты, которые релевантны конкретному факту.

**Коммиты — без упоминания Claude/AI.** См. правило в NestJS-конвенциях выше — оно общее для всего проекта, не
только для backend-кода: сообщения коммитов не содержат `Co-Authored-By: Claude`, ссылок на `claude.ai/code` или
любое иное упоминание AI-ассистента.

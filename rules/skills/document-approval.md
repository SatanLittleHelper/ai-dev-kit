# Document Approval (Plannotator, without Plan Mode)

Каждый документ на согласование (дизайн-спека, план тестов, план реализации, роадмап, черновик задачи) согласуется через Plannotator-аннотирование файла. Native Plan Mode (`EnterPlanMode` / `ExitPlanMode`) для этого **не используется**: фразы «enter Plan Mode», «Plan Mode file», «`ExitPlanMode`» в других правилах кита означают этот процесс. Адаптация имеет приоритет над требованием native Plan Mode из общих правил и из глобальных инструкций пользователя.

## Процесс

1. **Черновик — отдельный файл со стабильным путём:** `tmp/drafts/<doc-slug>.md` (абсолютный путь). Следующий документ — новый файл, не дописывай его в файл уже согласованного документа.
2. **Открой на согласование** через навык `plannotator-annotate`: инструмент `plannotator`, если он доступен, иначе CLI с историей версий в окружении процесса:
   ```bash
   env PLANNOTATOR_ANNOTATE_HISTORY=1 plannotator annotate <абсолютный-путь> --gate --json
   ```
   Не меняй ради этого глобальные настройки пользователя. CLI запускай через `Bash` с `run_in_background: true`.
3. **Исправления — в тот же файл по тому же пути**, затем открой его повторно: история версий Plannotator показывает дифф. Первая версия — основа для сравнения; дифф появляется после изменения файла и повторного открытия.
4. **Дождись итогового решения** (правила ожидания — `rules/skills/plannotator.md`: пустой вывод и таймаут опроса — не результат):
   - `annotated` — обработай замечания, исправь файл, открой повторно;
   - `approved` — документ согласован; примечания при `approved` учитывай как рекомендации, а не как запрос нового ревью;
   - `dismissed` — согласования нет, ничего не реализуй.
5. **После `approved`** сохрани документ в целевое место (путь — в правиле соответствующего документа) и удали черновик из `tmp/drafts/`. До `approved` в целевой путь не пиши.
6. Если песочница мешает запустить локальный сервер или записать историю Plannotator, запроси разрешения и повтори. Запуск без истории не считается успешной проверкой диффа.

## Ограничения

- Пока Plannotator-сессия не вернула итог, ход не заканчивай.
- Вопросы по содержанию документа задавай через `AskUserQuestion` или обычным текстом — Plan Mode не активен, ограничения «ход заканчивается только `ExitPlanMode`/`AskUserQuestion`» нет.
- Не требуй от пользователя `/plan` и не предлагай включить Plan Mode.
- До реализации получи явное согласование (`approved`) соответствующих документов.

## Common Mistakes

| Mistake | Fix |
|---|---|
| `EnterPlanMode` ради согласования документа | Черновик в `tmp/drafts/<slug>.md` + `plannotator-annotate` |
| Новый путь файла на каждой итерации | Один путь на документ — иначе нет диффа версий |
| Новый документ дописан в файл согласованного | Отдельный файл на каждый документ |
| Запись в целевой путь до `approved` | Сначала `approved`, потом сохранение и удаление черновика |
| Пустой вывод CLI принят за итог | Продолжай ждать итоговое решение |
